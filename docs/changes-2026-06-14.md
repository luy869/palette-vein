## 1. 埋め込みモデル比較と EVA02-B/16 採用

### 比較ハーネスの設計（コミット 6cba336）

壁紙サンプル250枚を使い、モデル間の品質を定量・定性の両面で比較するハーネス
`clip_service/eval_models.py` を作成した。

**評価対象**

| カテゴリ | モデル | 次元 |
|----------|--------|------|
| CLIP | ViT-B/32 openai（現行） | 512 |
| CLIP | ViT-B/16 laion2b_s34b_b88k | 512 |
| CLIP | EVA02-B/16 merged2b_s8b_b131k | 512 |
| CLIP | SigLIP i18n ViT-B/16 | 768 |
| CLIP | EVA02-L/14 merged2b_s4b_b131k | 768 |
| CLIP | ViT-L/14 laion2b_s32b_b82k | 768 |
| DINOv2 | ViT-S/14 | 384 |
| DINOv2 | ViT-B/14 | 768 |

**評価軸**

- テキスト→画像検索（CLIP系のみ）: 複数のクエリで上位 k 件を取得し視覚確認
- 画像→類似: 基準画像に対する上位 k 件の視覚的類似度
- 客観指標: 同一意味の日本語・英語テキスト4組（例:「夜の森と月明かり」/ "night forest and moonlight"）の
  埋め込みコサイン類似度（高いほど多言語対応が強い）

結果を `/tmp/model_eval.html` にモデル横並びで HTML 出力。

### 比較結果

- **SigLIP i18n**: 日英コサイン=0.829 で最高・最も安定。多言語（日本語クエリ）への対応が他を大幅に上回る（客観指標で確認）
- **EVA02-B/16**: 日英コサインは中位（0.698）。EVA系は同サイズCLIPの中で最強クラスとされ、アート系の品質を期待して採用（このデータでの目視確定は再埋め込み完了後に体感予定）
- **EVA02-L/14**: EVA系の上位。768次元
- **DINOv2**: テキスト入力なし。目視評価の結果 **CLIP系に対する明確なアドバンテージは無し**。
  ただし**他モデルと異なる画像を返す率が高く**、CLIPの意味的類似とは別軸（視覚的/構造的）として参考になる

### 採用判断: EVA02-B/16

**512次元据え置きが最大の決め手**。DBスキーマ・`backend/internal/recommend/profile.go` の
`embedDim` 定数・pgvector HNSW インデックスを一切変更せずにモデルを切り替えられる。

| 採用理由 | 詳細 |
|----------|------|
| スキーマ変更不要 | 512次元のまま。マイグレーション・全件再埋め込みの摩擦がない |
| アート品質 | EVA02系はイラスト・壁紙ジャンルとの相性が高いと判断 |
| VRAM | ViT-B/16 クラスは GTX1650S（4GB）でも安全 |
| 本番 DB がまっさらなタイミング | デプロイ前なので再埋め込みマイグレーション自体が不要 |

**見送ったモデル**

| モデル | 見送り理由 |
|--------|-----------|
| SigLIP i18n | 768次元→マイグレーション必須。さらに `open_clip` 以外の依存が増える可能性 |
| EVA02-L/14 | 768次元→マイグレーション必須 |
| DINOv2 | テキスト入力なし。テキスト検索とレコメンド（好みベクトル→類似検索）を兼用する現アーキテクチャと非互換 |

### コード変更（コミット ffc2452）

変更は `clip_service/server.py` の2箇所のみ。

```python
# 変更前
MODEL_NAME  = "ViT-B-32"
PRETRAINED  = "openai"

# 変更後
MODEL_NAME  = "EVA02-B-16"
PRETRAINED  = "merged2b_s8b_b131k"
```

EVA02 は標準 CLIP-BPE トークナイザを使うため、`EmbedText` の
`open_clip.tokenize` 呼び出しはコード変更不要だった。

あわせてウォームアップ処理をモデル非依存に汎用化した。

```python
# 変更前: 固定テンソル（入力解像度に依存する可能性）
dummy = torch.zeros(1, 3, 224, 224).to(device)

# 変更後: preprocess 経由（モデルが期待する入力解像度に自動で合う）
dummy = preprocess(Image.new("RGB", (256, 256))).unsqueeze(0).to(device)
```

## 2. DINOv2 と将来のハイブリッド

DINOv2（Meta）は自己教師あり学習でテキスト入力がなく、「画像→類似画像」に特化している。
ハーネスに追加して目視評価した結果、**CLIP系（EVA02-B/16）に対する明確なアドバンテージは無かった**。
ただし**他モデルとは異なる画像を返す率が高く**、CLIPの意味的類似とは別軸（視覚的/構造的）を捉えている。

**判断: 当面は単一モデル（EVA02-B/16）で進め、CLIP+DINOハイブリッドは見送り。**
現アーキテクチャはテキスト検索とレコメンドを同一CLIP空間で行うため、DINOv2を単独置換はできない。

将来の余地（採用条件付きで保留）:

- CLIP 埋め込み（テキスト+検索用）と DINOv2 埋め込み（画像→画像用）を両方保持し、推薦時にスコア融合
- **多様性/探索枠**としての活用（DINOv2が返す「違う画像」をフィルターバブル回避に使う）
- 着手条件: 画像→画像の品質向上 or 多様性の効果が明確に欲しくなった場合のみ
  （第2埋め込みカラム + 別次元の HNSW インデックスが必要）
