# changes 2026-07-10

推薦カードの概念タグ（reason_tags）が全画像で同一になるバグを修正

---

## 症状

おすすめタブのカードに並ぶ概念タグが、画像の内容によらずほぼ同一だった。
森・夕焼け・街並みの画像にまで「なびく髪」が付く。実質すべてのカードが
`なびく髪 / 柔らかい光のボケ / 空に映えるシルエット` の3タグを表示していた。

## 原因

`concepts.Tagger.Reason()` の `min(cos_img, cos_prof)` 方式。

`min(si, sp) <= sp` なので、**プロフィール側スコア `sp` がランキングの上限（天井）**になる。
`sp` は画像に依存しないため、天井の高いタグ（＝好みの上位タグ）が全画像で上位を占める。
画像固有の概念は、`si` がいくら高くても `sp` が低ければ `min` で潰されて消える。

さらに根本的には、`si` と `sp` は**同じ尺度で比較できない**。
プロフィールベクトルは多数のいいねの加重平均なので、個々の概念方向が相殺されて
ノルムあたりのスコアが個別画像より系統的に小さくなる。

### 実測（本番DB user_id=3 のいいね49件 + 実CLIP、2026-07-10）

`Reason()` の出力が `Top(profile)` の上位3件と重みの数値まで一致していた。

```
image 1415
  Reason        : bokeh(1.000), rainy(0.680), cool blue(0.576)
  Top(profile)  : bokeh(1.000), silhouette(0.693), rainy(0.680), cool blue(0.576)
                                                        ^^^^^        ^^^^^ 完全一致 = min が sp を返している
```

一方 `Top(image)` は画像固有だった（690→`cherry blossom sakura`, 7088→`deep red and crimson`,
2176→`flat design illustration`）。これらが `Reason` から丸ごと欠落していた。

## 修正

`Reason()` を「**好み側スコアが正のタグに絞り込み、その中を画像側スコアで順位付け**」に変更。

```go
for i, e := range t.embeds {
    if dotProd(profC, e) <= 0 {
        continue // 好みと反対方向の概念は候補から外す
    }
    scores[i] = float64(dotProd(imgC, e))
}
```

意味は保たれる: 「ユーザーが好む概念のうち、この画像が最も強く表しているもの」＝ 推薦理由。
スケールの異なる2値を比較しないので、天井による縮退が起きない。

### 検討して却下した案（実データで比較）

| 案 | 内容 | 結果 |
|----|------|------|
| B | 両側を z-score 化してから min | 改善するが bokeh が10画像中9枚で1位のまま |
| C | `si * sp`（積） | 画像間の差がほとんど出ない |
| E | `siZ + spZ`（和） | bokeh が全画像で1位。従来と大差なし |
| **D（採用）** | `sp > 0` で絞り `si` で順位付け | 全画像で固有タグが1位に出る |

### 修正後の実測

| 画像 | 修正前 | 修正後 |
|---|---|---|
| 690（桜） | bokeh, silhouette, rainy | **cherry blossom sakura**, bokeh, silhouette |
| 2176（フラットな街） | rainy, silhouette, bokeh | **flat design**, **low poly**, **pixel art** |
| 7088（赤い森） | bokeh, rainy, silhouette | **deep red and crimson**, bokeh, pixel art |
| 430（緑の風景） | bokeh, rainy, silhouette | **green nature and emerald**, rainy, bokeh |

## テスト

`backend/internal/concepts/tagger_test.go` を新規追加（従来テストなし）。

- `TestReasonIsImageSpecific` — 異なる画像には異なるタグが返ること（本バグの回帰防止）
- `TestReasonExcludesConceptsProfileDislikes` — 好みと反対方向の概念は、画像がどれだけ強く
  表していても推薦理由にしないこと
- `TestReasonNotReady` — Warmup 未完了時に nil（CLIP 未起動でも落ちない）

語彙と同数の直交基底をタグ埋め込みに使うことで、CLIP なしで決定的にテストできる。

## 影響範囲

- `Top()` は変更なし（パレットタブの概念タグ、`/api/profile/tags` の `tags` / `clusters`）。
- 変更は `Reason()` のみ = 推薦カードの `reason_tags` だけ。
- API のレスポンス形式は不変。フロントエンドの変更は不要。
